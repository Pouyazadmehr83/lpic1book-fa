کتاب LPIC-1 فارسی / آزمون ۱۰۲ / مبحث ۱۰۹: مبانی شبکه (Networking Fundamentals)

109.4 DNS سمت سرویس گیرنده را پیکربندی کنید

آزمون ۱۰۲ وزن: 2 مبحث ۱۰۹

وزن: 2

کاندیداها باید بتوانند DNS را روی یک میزبان مشتری پیکربندی کنند.

حوزه های دانش کلیدی

  • سرورهای DNS راه دور را پرس و جو کنید.
  • وضوح نام محلی را پیکربندی کنید و از سرورهای DNS راه دور استفاده کنید.
  • ترتیب انجام تفکیک نام را تغییر دهید.
  • خطاهای اشکال زدایی مربوط به وضوح نام
  • آگاهی از systemd-resolved

شرایط و امکانات

  • /etc/hosts
  • /etc/resolv.conf
  • /etc/nsswitch.conf
  • host
  • dig
  • getent

DNS

ما قبلاً چیزهای زیادی در مورد سیستم نام دامنه می دانیم. سرویسی که نام دامنه (مثلا yahoo.com) را به آدرس های IP (مثلا 206.190.36.45) ترجمه می کند. سرور DNS زمانی استفاده می شود که سروری را با استفاده از نام دامنه آن پینگ می کنید. شما فایل های پیکربندی DNS را مشاهده کرده اید و باید بدانید که سرور DNS واقعی که توسط رایانه استفاده می شود را می توان از /etc/resolv.conf (موقتا) بررسی کرد / تغییر داد:

دستور / کد ترمینال
$ cat /etc/resolv.conf
# Generated by NetworkManager
nameserver 192.168.1.1
nameserver 4.2.2.4

$ ping x.org
PING x.org (131.252.210.176) 56(84) bytes of data.
64 bytes from annarchy.freedesktop.org (131.252.210.176): icmp_seq=1 ttl=45 time=338 ms
64 bytes from  annarchy.freedesktop.org (131.252.210.176): icmp_seq=2 ttl=45 time=333 ms
^C
--- x.org ping statistics ---
2 packets transmitted, 2 received, 0% packet loss, time 1000ms
rtt min/avg/max/mdev = 333.088/335.612/338.136/2.524 ms

host

این یک برنامه ساده برای جستجوی پرس و جوهای DNS است. این یک نمونه بدون آرگومان است:

دستور / کد ترمینال
$ host kernel.org
kernel.org has address 139.178.84.217
kernel.org has IPv6 address 2604:1380:4641:c500::1
kernel.org mail is handled by 10 smtp1.kernel.org.
kernel.org mail is handled by 10 smtp2.kernel.org.
kernel.org mail is handled by 10 smtp3.kernel.org.

همانطور که می بینید، دستور host تمام رکوردهایی را که می تواند برای یک دامنه خاص پیدا کند، برمی گرداند. در این مورد IPv4 (A)، IPv6 (AAAA) و دو رکورد Mail (MX) را برمی گرداند.

اگر می‌خواهید فقط یک رکورد خاص را بررسی کنید، می‌توانید آن را از طریق -t سوئیچ ارائه کنید. بنابراین -t A فقط سوابق IPv4 را برمی گرداند.

حفاری

ابزار dig به طور خاص برای درخواست سرورهای DNS ساخته شده است. اگر می خواهید بدانید که x.org به کجا اشاره می کند، می توانید انجام دهید:

دستور / کد ترمینال
$ dig x.org

; <<>> DiG 9.10.3-P4-RedHat-9.10.3-12.P4.fc23 <<>> x.org
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NOERROR, id: 7483
;; flags: qr rd ra; QUERY: 1, ANSWER: 1, AUTHORITY: 0, ADDITIONAL: 1

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 512
;; QUESTION SECTION:
;x.org.                IN    A

;; ANSWER SECTION:
x.org.            1625    IN    A    131.252.210.176

;; Query time: 35 msec
;; SERVER: 192.168.1.1#53(192.168.1.1)
;; WHEN: Sun Apr 17 12:45:02 IRDT 2016
;; MSG SIZE  rcvd: 50

همانطور که می بینید، dig ** ip lookup برای x.org انجام داد و به من گفت که IP آن 131.252.210.176 است. 1625 TTL** یا Time To Live نامیده می شود و نشان می دهد که چند ثانیه این پاسخ در حافظه کش (Cache) معتبر در نظر گرفته می شود. این دستور همچنین به ما می گوید که از کدام سرور برای پرس و جو کردن پاسخ (4 خط آخر) استفاده می شود و چه زمانی و چقدر طول کشید.

همچنین راهی برای گفتن دستور dig وجود دارد که باید از چه سروری به عنوان DNS vi @<DNS-SERVER> استفاده کند:

در اینجا من از دیگ خواسته ام که از 8.8.8.8 به عنوان DNS خود استفاده کند و از google.com پرس و جو کند. می بینید که من بیش از یک پاسخ (در واقع خیلی بیشتر از یک پاسخ) دریافت کرده ام. رایانه من می تواند به طور تصادفی با هر یک از این IP ها تماس بگیرد تا به google.com برسد. به عبارت دیگر، google.com از بیش از یک سرور/IP استفاده می‌کند و 8.8.8.8 همه آنها را هنگام درخواست برای آن دامنه ارائه می‌کند.

/etc/hosts

این فایل حاوی آدرس های IP و نام های مربوط به آنها است. این یک نوع وضوح نام ثابت در رایانه شما است. بیایید نگاهی بیندازیم:

دستور / کد ترمینال
$ head /etc/hosts
127.0.0.1    funlife localhost.localdomain    localhost clickadu.com
::1    funlife localhost6.localdomain6    localhost6

10.159.32.155 nsproxy
172.16.12.134 linuxclass wonderland
193.40.12.135 salma

87.106.233.90 gratis.vps

192.168.59.231 mass1

این فایل را می توان با روت تغییر داد و برخی از نام های دامنه (localhost, mass1, gratis.vps, ...) را به برخی از آدرس های IP نگاشت می کند. اگر من روی این کامپیوتر mass1 را پینگ کنم، ببینیم:

دستور / کد ترمینال
$ dig mass1

; <<>> DiG 9.10.3-P4-RedHat-9.10.3-12.P4.fc23 <<>> mass1
;; global options: +cmd
;; Got answer:
;; ->>HEADER<<- opcode: QUERY, status: NXDOMAIN, id: 39464

;; OPT PSEUDOSECTION:
; EDNS: version: 0, flags:; udp: 512
;; QUESTION SECTION:
;mass1.                IN    A

;; AUTHORITY SECTION:
.            600    IN    SOA    a.root-servers.net. nstld.verisign-grs.com. 2016041700 1800 900 604800 86400

$ ping mass1
PING mass1 (192.168.59.231) 56(84) bytes of data.

From 85-15-16-103.shatel.ir (85.15.16.103) icmp_seq=2 Packet filtered

هنگامی که من برای mass1 می روم، کامپیوتر من 192.168.59.231 را پینگ می کند، حتی زمانی که DNS نمی تواند این نام را پیدا کند، زیرا در /etc/hosts تعریف شده است.

nsswitch

فایل /etc/nsswitch.conf اولویت جستجوها، بررسی رمز عبور، ... را به سیستم می گوید.

دستور / کد ترمینال
$ cat /etc/nsswitch.conf
#
# /etc/nsswitch.conf
#
# An example Name Service Switch config file. This file should be
# sorted with the most-used services at the beginning.
#
# The entry '[NOTFOUND=return]' means that the search for an
# entry should stop if the search in the previous entry turned
# up nothing. Note that if the search failed due to some other reason
# (like no NIS server responding) then the search continues with the
# next entry.
#
# Valid entries include:
#
#    nisplus            Use NIS+ (NIS version 3)
#    nis            Use NIS (NIS version 2), also called YP
#    dns            Use DNS (Domain Name Service)
#    files            Use the local files
#    db            Use the local database (.db) files
#    compat            Use NIS on compat mode
#    hesiod            Use Hesiod for user lookups
#    [NOTFOUND=return]    Stop searching if not found so far
#

# To use db, put the "db" in front of "files" for entries you want to be
# looked up first in the databases
#
# Example:
#passwd:    db files nisplus nis
#shadow:    db files nisplus nis
#group:     db files nisplus nis

passwd:     files sss
shadow:     files sss
group:      files sss

#hosts:     db files nisplus nis dns
hosts:      files mdns4_minimal [NOTFOUND=return] dns myhostname mymachines

# Example - obey only what nisplus tells us...
#services:   nisplus [NOTFOUND=return] files
#networks:   nisplus [NOTFOUND=return] files
#protocols:  nisplus [NOTFOUND=return] files
#rpc:        nisplus [NOTFOUND=return] files
#ethers:     nisplus [NOTFOUND=return] files
#netmasks:   nisplus [NOTFOUND=return] files

bootparams: nisplus [NOTFOUND=return] files

ethers:     files
netmasks:   files
networks:   files
protocols:  files
rpc:        files
services:   files sss

netgroup:   files sss

publickey:  nisplus

automount:  files sss
aliases:    files nisplus

در خط DNS من hosts: files mdns4_minimal [NOTFOUND=return] dns myhostname mymachines دارم. این بدان معناست که وقتی سیستم می خواهد آدرس IP یک نام را پیدا کند، ابتدا به دنبال files (/etc/hosts) و سپس برای mdns4_minimal و سپس dns و غیره می رود. در این مورد، اگر facebook.com را به /etc/hosts خود اضافه کنم، به این صورت:

دستور / کد ترمینال
127.0.0.1 facebook.com

و سپس مرورگر من را به facebook.com هدایت کنید، کامپیوتر من سعی می کند به جای IP واقعی فیس بوک به وب سرور در 127.0.0.1 متصل شود.

systemd-resolved

لازم به ذکر است که systemd یک DNS به نام systemd-resolved ارائه می دهد. به درخواست‌های DNS در 127.0.0.53 گوش می‌دهد و پس از مشورت با /etc/systemd/resolv.conf یا /etc/resolv.conf پاسخ می‌دهد.

بیشتر بخوانید اینجا درباره systemd-resolved.
