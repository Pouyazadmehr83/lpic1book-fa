## اهداف

* از دستورات تک پوسته و توالی دستورات یک خطی برای انجام کارهای اساسی در خط فرمان (Command Line) استفاده کنید.
* از محیط پوسته شامل تعریف، ارجاع و صادرات متغیرهای محیطی (Environment Variables) استفاده و اصلاح کنید.
* استفاده و ویرایش تاریخچه فرمان.
* فراخوانی دستورات در داخل و خارج از مسیر تعریف شده.

### Shells and Bash

<iframe width="560" height="315" src="https://www.youtube.com/embed/X-zq9-FhjOA" title="YouTube video player" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>

شما دستورات خود را در یک پوسته صادر می کنید. این رابط خط فرمان (Command Line) شماست و گزینه های مختلفی برای آن دارید. برای رسیدن به پوسته خود باید در حالت متنی وارد سیستم شوید یا یکی از *ترمینال شبیه سازهای* مختلف را در رابط کاربری گرافیکی خود اجرا کنید. برخی از نمونه‌ها `gnome-terminal`، `konsole`، `xterm`، و غیره هستند.

پس از اجرای Terminal Emulator یا ورود به حالت متنی، در پوسته هستید و می توانید دستوراتی را صادر کنید. اگرچه `bash` (پوسته GNU Bourne Again) رایج ترین است، ممکن است از `zsh`، `dash`، `ksh`، `csh` و دیگران استفاده کنید.

می‌توانید بررسی کنید که دستور عمومی `sh` شما به کجا پیوند می‌خورد

```
$ readlink /bin/sh
```

یا متغیر `$SHELL` خود را با استفاده از:

```
echo $SHELL
```

bash شما دارای برخی دستورات _internal_ است که بدون وابستگی خارجی آنها را می فهمد (مثلاً `cd`، `break`، `exec`، ...) اما اگر چیزی را به صورت داخلی درک نکرد، سعی می کند آن را به عنوان یک فایل اجرایی خارجی اجرا کند.

برای تعیین این مورد می توانید از دستور `type` استفاده کنید:

```
[jadi@fedora ~]$ type cd
cd is a shell builtin
[jadi@fedora ~]$ type ls
ls is aliased to `ls --color=auto'
[jadi@fedora ~]$ type ping
ping is /usr/bin/ping
```

## دستورات `cd`, `pwd` و `uname`
### سی دی
شما قبلاً تعداد زیادی دستور `cd` را دیده اید :) این *دایرکتوری (پوشه)* را تغییر می دهد، از جمله `.` (دایرکتوری (پوشه) فعلی) و `..` (دایرکتوری (پوشه) والد). 

شما می توانید به دو طریق به دایرکتوری (پوشه) ها اشاره کنید:

1. **مسیرهای مطلق**: مانند `/home/jadi/lpic1/lesson3.1`
2. **مسیرهای نسبی**: مانند `lpic1/lesson3.1`. در این مورد، ما در ابتدا `/` را اضافه نمی کنیم، بنابراین bash سعی می کند فهرست راهنمای `lpic1` را در جایی که ما هستیم (محلی / نسبی) پیدا کند.

> کاراکترهای `~` به معنی *دایرکتوری (پوشه) اصلی کاربر صادر کننده فرمان است*

همچنین امکان صدور `cd` بدون هیچ پارامتری وجود دارد. این شما را به فهرست اصلی خود منتقل می کند. بنابراین این 3 دستور همه برابر هستند:

```
cd
cd ~
cd $HOME
```

### pwd
دایرکتوری (پوشه) فعلی شما را به شما نشان می دهد:

```
[jadi@fedora lesson3.1]$ pwd
/home/jadi/lpic1/lesson3.1
```

### unname
اطلاعات مربوط به سیستم را به شما می دهد. سوئیچ های رایج عبارتند از:

| گزینه | توضیحات |
| :--- | :--- |
| -s | نام هسته را چاپ کنید. اگر گزینه ای مشخص نشده باشد، این پیش فرض است. |
| -n | نام گره یا نام میزبان را چاپ کنید. |
| -r | انتشار هسته را چاپ کنید. این گزینه اغلب با دستورات مدیریت ماژول استفاده می شود. |
| -v | نسخه کرنل را چاپ کنید. |
| -m | نام سخت افزار \(CPU\) دستگاه را چاپ کنید. |
| -o | نام سیستم عامل را چاپ کنید. |
| -a | تمام اطلاعات بالا را چاپ کنید. |

مثال:

```text
[jadi@fedora lesson3.1]$ uname -a
Linux fedora 5.14.0-60.fc35.aarch64 #1 SMP Mon Aug 30 16:30:42 UTC 2021 aarch64 aarch64 aarch64 GNU/Linux
```


## دریافت کمک
اکثر دستوراتی که ما استفاده می کنیم دارای یک کتابچه راهنمای جالب و کامل هستند که از طریق دستور `man` قابل دسترسی است. به طور پیش‌فرض از پیجر `less` استفاده می‌کند و حاوی اسناد، سوئیچ‌ها، پارامترها، ... دستورات و ابزارهای کمکی است. 

با خواندن کتابچه راهنمای فرمان `yes` خود را با مرد آشنا کنید:

```
$ man yes
```

لطفا توجه داشته باشید که صفحات man در بخش های مختلف (کتاب) دسته بندی شده اند. می توانید با خواندن دفترچه راهنمای مرد این موارد را بررسی کنید:

```
$ man man
$ man 5 passwd
```

## کاراکترهای ویژه و نقل قول/فرار
در دنیای کامپیوتر، برخی از شخصیت ها معانی خاصی دارند. برای مثال در bash، نویسه `*` به همه فایل‌ها گسترش می‌یابد. در این مواقع، اگر می خواهید از این کاراکتر بدون این بسط استفاده کنید، باید آن را *نقل** یا *Escape* انجام دهید. در بسیاری از موارد این کار با افزودن یک کاراکتر `\` قبل از آن انجام می شود:

```
$ echo 2 \* 3 = 6
2 * 3 = 6
```

اگر از آنها در دستورات خود استفاده می کنید، اینها شخصیت هایی با معانی خاصی هستند که باید آنها را نقل کنید:

`* ?[]'"\$;&()|^<>`

لطفاً توجه داشته باشید که یک کاراکتر فاصله در لیست کاراکترهای بالا وجود دارد.

> همانطور که می بینید، `\` معنای خاصی دارد، بنابراین اگر می خواهید از خود اسلش عقب استفاده کنید (بدون استفاده از آن)، باید اسلش پشت خود را با اسلش عقب دیگر `\\` * نقل قول کنید.

علاوه بر فرار، می‌توانید از `\` برای ایجاد چند کاراکتر خاص استفاده کنید. برای مثال، چون نمی‌توانید کاراکتر *return* را تایپ کنید، آن را از طریق `\n` (خط جدید) ایجاد می‌کنید:

```text
jadi@funlife:~$ echo -e "hello\nthere"
hello
there
```

برخی موارد دیگر عبارتند از:

| تابع دنباله فرار |  |
| :--- | :--- |
| \a | هشدار \(زنگ\) |
| \b | بک اسپیس |
| \c | سرکوب خط جدید انتهایی \(عملکرد مشابه با -n گزینه\) |
| \f | فید فرم \(پاک کردن صفحه در یک نمایشگر ویدیو\) |
| \n | خط جدید |
| \r | بازگشت کالسکه |
| \t | زبانه افقی |

در bash می‌توانید از `\` برای شکستن یک فرمان به خطوط بیشتر استفاده کنید:

```
$ echo You know slashes! But this \
is another \
usage
You know slashes! But this is another usage
```



## متغیرهای محیط پوسته

<iframe width="560" height="315" src="https://www.youtube.com/embed/KMvc1SyPgjw" title="YouTube video player" frameborder="0" allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture" allowfullscreen></iframe>

*متغیرهای محیط* حاوی برخی تنظیمات و اطلاعات در مورد پوسته است. برای مثال، ویرایشگر پیش‌فرض شما در متغیر `EDITOR` تنظیم شده است. شما می توانید مقدار یک متغیر پوسته را به صورت زیر جستجو کنید:

```
[jadi@fedora ~]$ echo $EDITOR
/usr/bin/nano
```

با استفاده از دستور `set` یا `env` می توان همه متغیرهای env را بررسی کرد. 

اینها برخی از پرکاربردترین متغیرهای محیط bash هستند:


| نام | تابع |
| :--- | :--- |
| کاربر | نام کاربری که وارد شده است |
| مسیر | فهرست دایرکتوری (پوشه) ها برای جستجوی دستورات، دو نقطه جدا شده |
| ویرایشگر | ویرایشگر پیش فرض |
| HISTFILE | جایی که bash باید تاریخچه خود را ذخیره کند (به طور معمول `.bash_history`) |
| HOSTNAME | نام میزبان سیستم |
| PS1 | اعلان! بازی با آن |
| UID | شناسه کاربری عددی کاربر وارد شده |
| صفحه اصلی | فهرست اصلی کاربر |
| PWD | فهرست کار فعلی |
| SHELL | نام پوسته |
| $ | شناسه فرآیند \(یا PID پوسته bash در حال اجرا \(یا سایر\) فرآیند |
| PPID | شناسه فرآیندی که این فرآیند را شروع کرده است \(یعنی شناسه فرآیند والد\) |
| ? | کد خروج آخرین دستور |

هنگام تلاش برای دسترسی به مقدار، باید یک `$` را به ابتدای نام متغیر اضافه کنید.

```text
$ echo $USER $UID
jadi 1000
$ echo $SHELL $HOME $PWD
/bin/bash /home/jadi /home/jadi/lpic
```

برای تعریف یک EV (متغیر محیطی) جدید یا تغییر یا حذف یکی، می‌توانیم انجام دهیم:

```text
$ MYMOOD=happy
$ echo I am $MYMOOD
I am happy
$ MYMOOD="Even Happier" # space has a specific meaning
$ unset MM
```

اگر می‌خواهید برنامه‌های جدیدی که از این پوسته شروع می‌شوند به متغیری که تعریف کرده‌اید دسترسی داشته باشند، باید آنها را با `export` تنظیم کنید یا بعداً صادر کنید.

```
$ export MYMOOD
$ export YOURMOOD="Not Confused"
```

> پیکربندی‌های bash جهانی در `/etc/profile` ذخیره می‌شوند و هر کاربر پیکربندی خود را در `~/.profile` و `~/.bash\_profile` و `~/.bash\_logout` دارد. اگر نیاز به تغییر دائمی دارید، تنظیمات خود را به این موارد اضافه کنید.

## مسیر
وقتی فرمانی را صادر می کنید، اگر فرمان bash داخلی باشد، bash اجرا می شود. در غیر این صورت، bash می رود و متغیرهای `PATH` را یکی یکی بررسی می کند و سعی می کند آنها را در آنجا پیدا کند. اگر نه، به شما خطا می دهد. اگر می خواهید چیزی را در یک مسیر خاص اجرا کنید، باید به طور انحصاری مکان را توصیف کنید:

```text
$ echo $PATH
/home/jadi/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games
```

اما اگر بخواهم `tar` را اجرا کنم چه اتفاقی می افتد؟ بیایید با دستورات `which`، `type`، و `whereis` بررسی کنیم:

```
jadi@funlife:~$ which tar
/bin/tar
jadi@funlife:~$ type tar
tar is /bin/tar
jadi@funlife:~$ whereis tar
tar: /usr/lib/tar /bin/tar /usr/include/tar.h /usr/share/man/man1/tar.1.gz
```

یک مثال جالب تر `ping` در فدورا است:

```
[jadi@fedora ~]$ whereis ping
ping: /usr/bin/ping /usr/sbin/ping /usr/share/man/man8/ping.8.gz
[jadi@fedora ~]$ which ping
/usr/bin/ping
[jadi@fedora ~]$ /usr/sbin/ping 4.2.2.4
PING 4.2.2.4 (4.2.2.4) 56(84) bytes of data.
64 bytes from 4.2.2.4: icmp_seq=1 ttl=50 time=160 ms
```

> به همین دلیل است که وقتی می خواهید بگویید "run this_program in this directory" "./this_program" را صادر می کنید. شما به طور انحصاری به bash می گویید که فایل کجاست. در لینوکس، دایرکتوری (پوشه) فعلی (.) به طور پیش فرض بخشی از PATH نیست.

## تاریخچه فرمان
Bash تاریخچه خود را در `~/.bash_history` ذخیره می کند. می توانید آن را `cat` کنید و محتوای آن را ببینید یا دستور `history` را اجرا کنید. همچنین می توانید از کلیدهای زیر (ترکیب) برای دسترسی به دستورات قبلی خود استفاده کنید:

| کلید (ترکیب) | استفاده |
|-|-|
| فلش بالا و پایین | حرکت در تاریخ |
| Ctrl+R | جستجوی عقب |
| Ctrl+O | دستوری را که پیدا کردید با Ctrl+R | اجرا کنید
| !! | آخرین دستور |
| !10 | دستور شماره 10 را اجرا کنید |
| !text | متن را به عقب جستجو کنید و اولین دستور پیدا شده | را اجرا کنید

> اگر می‌خواهید سابقه خود را پاک کنید، «HISTSIZE=0» را صادر کنید

## خروج از پوسته

دستور `exit` از پوسته خارج می شود. مانند CTRL+d.

اگر دستوری را در داخل پرانتز اجرا کنید، آن دستور در یک پوسته فرعی اجرا می‌شود و `exec` دستوری را اجرا می‌کند و پوسته فعلی را می‌بندد.
