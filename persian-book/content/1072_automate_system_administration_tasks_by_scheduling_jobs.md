موارد زیادی وجود دارد که باید برخی از دستورات را در زمان ها یا بازه های زمانی مشخص اجرا کنیم. به عنوان مثال ممکن است بخواهید فرآیند پشتیبان گیری خود را هر روز صبح ساعت 03:00 انجام دهید یا لیست فایل ها را در فهرست وب خود به صورت ساعتی بازخوانی کنید.

روش های مختلفی برای انجام این کار در دنیای لینوکس وجود دارد. متداول‌ترین موارد عبارتند از `crontab` برای اجرای وظایف در فواصل زمانی خاص، `at` برای اجرای دستورات در زمان خاص و همچنین ابزارهای کمکی ارائه شده توسط `systemd`.

### فرمت Crontab
Crontab با یک فایل پیکربندی کار می کند که به آن می گوید چه زمانی یک دستور را اجرا کند. به عنوان مثال می توانید بگویید "دستورات من را زمانی که ساعت 03 است و دقیقه 00 است اجرا کنید" یا "دستور من را زمانی که شنبه و ساعت 10 است و دقیقه 00 است اجرا کنید" یا "هر وقت دقیقه 00 باشد اجرا کنید". 

هر خط پیکربندی crontab دارای 6 فیلد است. 5 مورد اول یک بازه زمانی خاص را مشخص می کند و هر بعد از آن به عنوان "فرمان" استفاده می شود.

```
A    B    C    D    E    command and arguments
```

| ثبت شده | معنی | ارزش ها |
| :---: | :--- | :--- |
| A | دقیقه | 0-59 |
| B | ساعت | 0-23 |
| ج | روز ماه | 1-31 |
| D | ماه | 1-12 \(یا نام ها، در زیر ببینید\) |
| E | روز هفته | 0-7 \(0 یا 7 یکشنبه است یا از نام ها استفاده کنید\) |


اگر یک فیلد را با `*` جایگزین کنید، به معنای «هر چیزی» یا «همه» یا «هر کدام» است. همچنین اگر به جای فیلدهای زمان، `@reboot` یا `@daily` دارید، دستور یک بار پس از راه اندازی مجدد یا روزانه اجرا می شود. بیایید چند نمونه را ببینیم:

```text
5 0 * * *       $HOME/bin/daily.job >> $HOME/tmp/out 2>&1

# run at 2:15pm on the first of every month -- output mailed to paul
15 14 1 * *     $HOME/bin/monthly

# run at 10 pm on weekdays, annoy Joe
0 22 * * 1-5    mail -s "It's 10pm" joe%Joe,%%Where are your kids?%

23 0-23/2 * * * echo "run 23 minutes after midn, 2am, 4am ..., everyday"
5 4 * * sun     echo "run at 5 after 4 every sunday"

*/5 * * * *    echo "each 5 mintues"

42 8,18 * * 1-5    echo "8:42 and 18:42 and only on weekdays (monday till friday)"

@reboot        echo "runs after the reboot"
```

همانطور که در مثال‌های بالا مشاهده می‌کنید، می‌توان از `/` برای برش زمان استفاده کرد (بنابراین `*/5` به دقیقه یعنی هر پنج دقیقه) یا از `,` برای نشان دادن بیش از یک عدد استفاده کنید (بنابراین `8,18` به معنای 8 و 18 است).

> هنگام استفاده از `*` در اولین فایل، دستور خود را در هر دقیقه اجرا می کنید.

> چیزی شبیه `42 8 1 1 0` فقط زمانی اجرا می شود که اول ژانویه یکشنبه باشد!

هنگامی که یک cron اجرا می شود، خروجی برای صاحب cron ایمیل می شود.

### کرون های خاص کاربر

Cron یک سرویس لینوکس است. برای دیدن cron های خود می توانید از `crontab -l` \(list\) و برای ویرایش آنها می توانید از `crontab -e` \(edit\) استفاده کنید که فایل های cron را با یک ویرایشگر ویژه باز می کند و بعد از اتمام کار کرون های شما را اعتبارسنجی و بارگذاری می کند.

فایل‌ها در `/var/spool/cron/tabs/` یا `/var/spool/crontabs` ذخیره می‌شوند:

```text
# cat /var/spool/cron/tabs/jadi
# DO NOT EDIT THIS FILE - edit the master and reinstall.
# (/tmp/crontab.khObLu installed on Thu Oct 29 22:04:43 2023)
# (Cronie version 4.2)
# Example of job definition:
# .---------------- minute (0 - 59)
# |  .------------- hour (0 - 23)
# |  |  .---------- day of month (1 - 31)
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr ...
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat
# |  |  |  |  |
# *  *  *  *  * command to be executed
* * * * * date >> /tmp/date.cron.txt
```

> هرگز این فایل ها را مستقیما ویرایش نکنید. به جای آن از `crontab -e` استفاده کنید.

### کرون گسترده سیستم

فایلی به نام `/etc/crontab` وجود دارد. به نظر می‌رسد این یک فایل کاربر عادی است که با `crontab -e` باز شده است، اما یک فایل اضافی دارد:

```text
A    B    C    D    E    USER    command and arguments
```

این فایل باید مستقیماً با یک ویرایشگر ویرایش شود و می توان اشاره کرد که کدام کاربر این دستورات را اجرا می کند.

```text
# cat /etc/crontab
SHELL=/bin/sh
PATH=/usr/bin:/usr/sbin:/sbin:/bin:/usr/lib/news/bin
MAILTO=root
#
# check scripts in cron.hourly, cron.daily, cron.weekly, and cron.monthly
#
-*/15 * * * *   root  test -x /usr/lib/cron/run-crons && /usr/lib/cron/run-crons >/dev/null 2>&1
```

> توجه: به سه خط اول نگاهی بیندازید. پوسته ای که دستورات را اجرا می کند و متغیر PATH به علاوه اینکه چه کسی ایمیل های خروجی را دریافت می کند را پیکربندی می کند.

همانطور که می بینید این crontab پیش فرض کرون های دیگری را اجرا می کند! این کرون های ساعتی، روزانه، هفتگی و ماهانه هستند. بیایید در بخش بعدی نگاهی به آنها بیندازیم.

### سیستم ساعتی، روزانه، هفتگی، ماهانه، .. کرون

ما چند فایل crontab سطح سیستم را در `/etc/cron.d/` نیز داریم. آنها شبیه فایل های crontab عمومی هستند. به عنوان مثال این یکی است که برنامه `munin` ایجاد می کند:

```
$ cat /etc/cron.d/munin
#
# cron-jobs for munin
#

MAILTO=root

*/5 * * * *     munin if [ -x /usr/bin/munin-cron ]; then /usr/bin/munin-cron; fi
14 10 * * *     munin if [ -x /usr/share/munin/munin-limits ]; then /usr/share/munin/munin-limits --force --contact nagios --contact old-nagios; fi
19:12:37 jadi@ocean:~$ cat /etc/cron.weekly/man-db
```


اما دایرکتوری (پوشه) هایی به نام های `cron.hourly`، `cron.daily`، `cron.weekly` و `cron.monthly` نیز وجود دارد. همانطور که از نام آنها مشخص است، هر اسکریپت / فایلی که در آنها قرار دهید، به صورت ساعتی، روزانه، هفتگی و ماهانه اجرا می شود. این کار پاکسازی عمومی، پشتیبان گیری و ... را بسیار تمیزتر می کند. کافی است اسکریپت خود را در هر یک از این دایرکتوری (پوشه) ها کپی کنید و اجازه دهید در این بازه ها اجرا شوند.

```
$ sudo tree /etc/cron*
/etc/cron.d
├── munin
├── munin-node
├── php5
└── sendmail
/etc/cron.daily
├── apache2
├── apport
├── apt
├── aptitude
├── bsdmainutils
├── dpkg
├── logrotate
├── man-db
├── mlocate
├── passwd
├── popularity-contest
├── sendmail
├── update-notifier-common
└── upstart
/etc/cron.hourly
/etc/cron.monthly
/etc/crontab [error opening dir]
/etc/cron.weekly
├── apt-xapian-index
├── fstrim
├── man-db
└── update-notifier-common
```

بیایید نگاهی به یکی از فایل های cron.d بیندازیم:

```
$ cat /etc/cron.daily/mlocate
#! /bin/bash

set -e

[ -x /usr/bin/updatedb.mlocate ] || exit 0

if which on_ac_power >/dev/null 2>&1; then
    ON_BATTERY=0
    on_ac_power >/dev/null 2>&1 || ON_BATTERY=$?
    if [ "$ON_BATTERY" -eq 1 ]; then
	exit 0
    fi
fi

# See ionice(1)
if [ -x /usr/bin/ionice ] &&
    /usr/bin/ionice -c3 true 2>/dev/null; then
    IONICE="/usr/bin/ionice -c3"
fi

flock --nonblock /run/mlocate.daily.lock $IONICE /usr/bin/updatedb.mlocate
```
### در
ما می گوییم که crontab دستورات را در فواصل زمانی مشخص اجرا می کند، اما اگر لازم باشد یک دستور را فقط یک بار اجرا کنید چه اتفاقی می افتد؟ اینجا `at` دوست شماست.

```text
$ at now + 1 min
warning: commands will be executed using /bin/sh
at> touch /tmp/at
at> <EOT>
job 3 at Thu Oct 29 22:12:00 2015
```

> توجه: مثل همیشه در پایان ورودی Ctrl+D را فشار می دهیم

اگر می‌خواهید بررسی کنید چه چیزی در صف است، می‌توانید از `atq` استفاده کنید و سپس `atrm 4` را برای حذف شغل شماره 4 امتحان کنید.

```text
$ at teatime
warning: commands will be executed using /bin/sh
at> echo "tea time is 4pm"
at> <EOT>
job 4 at Fri Oct 30 16:00:00 2015
jadi@funlife:~$ at tomorrow
warning: commands will be executed using /bin/sh
at> echo "tomorrow this time"
at> <EOT>
job 5 at Fri Oct 30 22:15:00 2015
jadi@funlife:~$ at 17:30
warning: commands will be executed using /bin/sh
at> echo "this is the first 17:30"
at> <EOT>
job 6 at Fri Oct 30 17:30:00 2015
jadi@funlife:~$ atq
5    Fri Oct 30 22:15:00 2015 a jadi
4    Fri Oct 30 16:00:00 2015 a jadi
6    Fri Oct 30 17:30:00 2015 a jadi
jadi@funlife:~$ atrm 4
jadi@funlife:~$ atq
5    Fri Oct 30 22:15:00 2015 a jadi
6    Fri Oct 30 17:30:00 2015 a jadi
```

### مدیریت دسترسی cron

برای کنترل دسترسی به سیستم cron 4 فایل داریم:

```text
/etc/cron.allow
/etc/cron.deny

/etc/at.allow
/etc/at.deny
```

در اکثر سیستم ها هیچ یک از این فایل ها وجود ندارد اما اگر آنها را ایجاد کنید به صورت زیر فعال می شوند:

| پسوند فایل | قابلیت |
| :--- | :--- |
| .اجازه | فقط کاربران ذکر شده در این فایل مجاز به اجرای این سرویس هستند. همه کاربران دیگر رد خواهند شد |
| .انکار | همه می توانند از این سرویس استفاده کنند به جز کاربران ذکر شده در این فایل |

## systemd & systemd-run
امروزه اکثر توزیع‌های گنو/لینوکس از `systemd` استفاده می‌کنند که **تایمر** خود را به عنوان جایگزینی برای cron برای زمان‌بندی وظایف شما دارد. فایل‌های واحد تایمر از پسوند `.timer` استفاده می‌کنند، و برای هر یک از آنها باید یک فایل واحد مربوطه وجود داشته باشد که واحدی را که با فعال شدن تایمر فعال می‌شود، توصیف کند. به‌طور پیش‌فرض، یک تایمر سرویسی را با همین نام، به جز پسوند، فعال می‌کند.

تایمرها یک بخش [تایمر] دارند که مشخص می کند کارهای برنامه ریزی شده چه زمانی باید اجرا شوند. دو نوع تایمر وجود دارد. یکی **تایمر بیدرنگ** است که با گزینه `OnCalendar=` کار می کند و نوعی تایمر نزدیک به cron را تعریف می کند (بر اساس عبارات رویداد تقویم). این نحو است:

```
OnCalendar=DayOfWeek Year-Month-Day Hour:Minute:Second
```

> DayOfWeek اختیاری است و می توانید از مخفف 3 حرفی استفاده کنید (مثلا Mon)

`*`، `/` و `,` در پیکربندی های systemd و cron یکسان کار می کنند، اما در systemd نیز می توانید از `..` بین دو مقدار برای نشان دادن یک محدوده به هم پیوسته استفاده کنید. 


به عنوان مثال، برای اجرای سرویس با نام `/etc/systemd/system/myservice.service` در ساعت 02:42 روز شنبه اول هر ماه، این خط پیکربندی باید به فایل واحد `/etc/systemd/system/myservice.timer` اضافه شود.

```
[Unit]
Description=Run the blah blah service

[Timer]
OnCalendar=Sat *-*-1..7 02:42:00
Persistent=true

[Install]
WantedBy=timers.target
```

همچنین امکان تعریف تایمر **یکنواخت** وجود دارد. آنها پس از گذشت مدتی از یک نقطه شروع خاص (مثلاً زمانی که دستگاه بوت شده است یا زمانی که خود تایمر فعال شده است) فعال می شوند. می توانید بین یکی از موارد زیر یکی را انتخاب کنید:

| پیکربندی | معنی |
| ------ | ------- |
| OnActiveSec | زمان پس از فعال سازی واحد |
| OnBootSec | زمان پس از بوت شدن سیستم |
| OnStartupSec | زمان پس از راه اندازی مدیر سرویس برای خدمات سیستم، این تقریباً برابر با OnActiveSec است. از این برای خدمات کاربر استفاده کنید که در آن مدیر سرویس با ورود کاربر شروع شده است. |
| OnUnitActiveSec | زمان پس از آخرین فعال شدن سرویس مربوطه |
| OnUnitInactiveSec |  زمان پس از آخرین بار غیرفعال شدن سرویس مربوطه |

و شما می توانید از هر یک از usec، msec، ثانیه ها، دقیقه ها، ساعت ها، روزها، هفته ها، ماه ها، سال های قبل استفاده کنید. بنابراین به عنوان مثال 

```
[Timer]
OnUnitActiveSec=5minutes 20seconds
```

واحد مربوطه را 5 دقیقه و 20 ثانیه پس از آخرین فعال سازی این سرویس واحد فعال می کند.

لطفاً توجه داشته باشید که پس از افزودن هر تایمر، باید آن را فعال کنید (و احتمالاً شروع کنید):

```
# systemctl enable myservice.timer
# systemctl start myservice.timer
```

و همچنین فراموش نکنید که بعد از هر تغییر یک `systemctl daemon-reload` انجام دهید.

برای بررسی همه کارهای برنامه ریزی شده، دستور `systemctl list-timers` را اجرا کنید. این تمام تایمرهای فعال را به شما نشان می دهد. از کلید `--all` برای بررسی همه استفاده کنید.

میانبرهای کمی برای زمان ها نیز وجود دارد. می توانید به جای فرمت cron برای تنظیم تایمر از این موارد استفاده کنید:

| میانبر | وقتی اجرا می شود |
| -------- | ------------ |
| ساعتی | شروع هر ساعت |
| روزانه | یک روز در نیمه شب |
| هفتگی | نیمه شب دوشنبه |
| ماهانه | نیمه شب اول هر ماه |
| سالانه | نیمه شب اول ژانویه |

این یک نمونه از نصب اخیر فدورا است:

```
# cat system/timers.target.wants/plocate-updatedb.timer 
[Unit]
Description=Update the plocate database daily

[Timer]
OnCalendar=daily
RandomizedDelaySec=12h
AccuracySec=20min
Persistent=true

[Install]
WantedBy=timers.target
```

اگر می‌خواهید خروجی تایمرهای خود را بررسی کنید، می‌توانید از `journalctl` استفاده کنید.

> مانند هر فعالیت `systemd` دیگری، از سوئیچ `--user` برای استفاده در سطح کاربری خود و نه در سطح سیستم استفاده کنید.

در پایان باید از دستور `systemd-run` اطلاع داشته باشید. می تواند یک سرویس یا محدوده گذرا را راه اندازی کند و دستورات خاصی را در آن اجرا کند. 

بنابراین دستوری مانند:

```
systemd-run --on-active="2hours" --unit="helloworld.service"
```

helloworld.service را هر 2 ساعت یکبار اجرا می کند:

```
sudo systemd-run --on-active="2hours" /usr/local/bin/helloworld.sh --language=en_US
```

آن اسکریپت خاص را با پارامترهای نشان داده شده هر 2 ساعت اجرا می کند.
